# Vireqo Database Setup

Vireqo supports two database modes:

- SQLite for local development.
- PostgreSQL for production.

Sprint 5.0 adds production PostgreSQL verification so deployment issues are caught before real users hit the app.

## Local SQLite

SQLite still works for quick local testing:

```bash
cd backend
source .venv/bin/activate
python -m uvicorn app.main:app --reload --reload-dir app
```

With the default `DATABASE_URL=sqlite:///./vireqo.db`, the app can auto-create tables in development.

## Local PostgreSQL with Docker

From the project root:

```bash
docker compose up -d database
```

Then update `backend/.env`:

```env
DATABASE_URL=postgresql+psycopg://vireqo:vireqo_dev_password@localhost:5432/vireqo
AUTO_CREATE_TABLES=false
SEED_DEMO_DATA=true
```

Install dependencies:

```bash
cd backend
source .venv/bin/activate
pip install -r requirements.txt
```

Run migrations:

```bash
alembic upgrade head
```

Verify PostgreSQL readiness:

```bash
python scripts/postgres_smoke_test.py --require-postgres
```

Start the backend:

```bash
python -m uvicorn app.main:app --reload --reload-dir app
```

## Health checks

General API health:

```text
/health
```

Database readiness:

```text
/health/db
```

`/health/db` connects to the configured database and returns a safe redacted database target label. It does not expose credentials.

## Production database checklist

- `DATABASE_URL` points to PostgreSQL.
- `AUTO_CREATE_TABLES=false`.
- `SEED_DEMO_DATA=false`.
- `alembic upgrade head` runs successfully.
- `python scripts/postgres_smoke_test.py --require-postgres` passes.
- `/health/db` returns `status: ready` after deployment.

## Create future migrations

After changing SQLAlchemy models:

```bash
cd backend
source .venv/bin/activate
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

Review autogenerated migrations before committing them.

## Important note about old SQLite data

Sprint 5.0 verifies PostgreSQL readiness. It does not automatically copy records from an existing `backend/vireqo.db` file into PostgreSQL. For launch, start with a fresh PostgreSQL database or create a separate data export/import migration later.
