# Vireqo Database Setup

Sprint 4.0 moves Vireqo toward a production database foundation.

## Local SQLite

SQLite still works for quick local testing:

```bash
cd backend
source .venv/bin/activate
python -m uvicorn app.main:app --reload --reload-dir app
```

With the default `DATABASE_URL=sqlite:///./vireqo.db`, the app can still auto-create tables in development.

## Local PostgreSQL with Docker

From the project root:

```bash
docker compose up -d database
```

Then update `backend/.env`:

```env
DATABASE_URL=postgresql+psycopg://vireqo:vireqo_dev_password@localhost:5432/vireqo
AUTO_CREATE_TABLES=false
SEED_DEMO_DATA=true
```

Install dependencies:

```bash
cd backend
source .venv/bin/activate
pip install -r requirements.txt
```

Run migrations:

```bash
alembic upgrade head
```

Start the backend:

```bash
python -m uvicorn app.main:app --reload --reload-dir app
```

## Check database connectivity

```bash
cd backend
source .venv/bin/activate
python scripts/check_database.py
```

## Create future migrations

After changing SQLAlchemy models:

```bash
cd backend
source .venv/bin/activate
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

Review autogenerated migrations before committing them.

## Important note about old SQLite data

This patch prepares PostgreSQL for production. It does not automatically copy records from an existing `backend/vireqo.db` file into PostgreSQL. For launch, start with a fresh PostgreSQL database or create a separate data export/import migration later.
